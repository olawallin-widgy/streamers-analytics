## 🔴 HIGH

### BUG-1 — Messaging page is broken (shows "casino offer unavailable")
**Page:** `/messages` (logged-in) · **Devices:** ALL 6
`/messages` does not render a messaging UI. Instead it shows a *"Continue to Casino — This casino offer is unavailable. Please check the link and try again."* card. Confirmed identical on iPhone (WebKit) and Desktop Chrome — universal, not device-specific.
**Reproduce:** Log in → go to `/messages` → observe casino-offer error instead of inbox.
**Expected:** Member messaging inbox. **Actual:** Casino-offer error component.
_Caveat: verify whether email-verification gates this._

### BUG-2 — Tokens page is broken (shows "casino offer unavailable")
**Page:** `/tokens` (logged-in) · **Devices:** ALL 6
Same broken "Continue to Casino — casino offer unavailable" render as `/messages`. (Note: token buy/spend isn't live yet per product — but the page should not show a broken casino-offer error to members.)

### BUG-3 — Token purchase page is a hard 404
**Page:** `/tokens/purchase` (logged-in) · **Devices:** ALL 6
Returns the 404 page: *"404 Page Not Found — Oops! The page you're looking for seems to have vanished into the golden abyss."* Title renders as `tokens/purchase - Feist.tv`.

### BUG-4 — Misfiring API call: `/api/casino-offers/<page>/share` → 404
**Devices:** ALL (console error on 5; Firefox hides detail)
Multiple routes fire a GET to `https://api.jackpotstreamers.com/api/casino-offers/{PAGE}/share` that 404s, throwing a console error. Observed slugs: `become-a-model`, `contact`, `messages`, `tokens`, `account`. Looks like a share/meta feature wrongly prefixing every route with `casino-offers/`. Likely the same root cause as BUG-1/BUG-2.

### BUG-5 — Logged-out visitors cannot browse performers at all
**Pages:** `/performers` + every `/performer/*` · **Devices:** ALL 6
When logged out, the performer listing and all 7 performer profiles redirect to `/login`. Anonymous visitors can see nothing but the homepage — major concern for SEO, conversion, and first impressions at launch. **Confirm whether this is intended.**

## 🟡 MEDIUM

### BUG-6 — Settings avatar uses a dev placeholder that fails (TLS error)
**Page:** `/settings` (logged-in)
Avatar loads `https://via.placeholder.com/100`, which fails with a TLS error → broken/blank avatar. Leftover placeholder in production.

### BUG-7 — "testonlyaccount" performer card shows an image-upload dropzone
**Page:** `/performers` (logged-in), performer grid
The `testonlyaccount` card renders a raw upload dropzone ("drop your image… JPEG and PNG") instead of a photo or fallback avatar. Performers without an image leak the upload widget into the public grid. (Also suggests `testonlyaccount` is test data that should be removed before launch.)

### BUG-8 — Stray "Field is" empty input leaking above the footer
**Pages:** site-wide (seen on performer profile, `/tokens`, `/messages`)
An unlabeled/empty input box labeled "Field is" renders just above the footer on multiple pages — looks like an unfinished/broken component rendered globally.

### BUG-9 — Console errors on logged-out legal/info pages
**Pages:** `/privacy`, `/terms`, `/kyc`, `/contact`, `/become-a-model` · **Devices:** 5
Same `casino-offers/{page}/share` 404 (BUG-4) fires on public pages too. Groups with BUG-4 but listed for logged-out coverage.

## 🟢 LOW

**Devices:** iPhone 14 Pro, Samsung Galaxy S23 (every page)
